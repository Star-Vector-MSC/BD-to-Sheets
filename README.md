# Проекты выгрузок БД → Google Sheets

Доступные выгрузки:

- `export_orders.py` — заказы WB дважды в день, в 08:00 и 20:00 МСК по артикулу WB и wild в явно заданные листы. [Настройка и расчёт](README_orders.md).
- `export_payments.py` — история платежей WB, существующая ежедневная задача. [Настройка](README_payments.md).
- `update_prices.py` — разовое обновление плановых цен, сначала предпросмотр. [Инструкция](README_prices.md).

Рабочие значения таблиц, адрес БД, `.env`, ключи и содержимое `runs/` не публикуются.
Установите зависимости в собственное окружение проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для новой установки скопируйте `.env.example` в `.env`, заполните локально и выдайте сервисному аккаунту доступ к нужным таблицам. Можно использовать существующий внешний `.env`; секреты копировать не требуется. Не коммитьте локальную конфигурацию.

Проверки без сетевых запросов и записей в таблицы:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

## Размещение новых выгрузок

Этот репозиторий — общий каталог проектов выгрузок. Каждая новая самостоятельная выгрузка размещается в собственной подпапке корня, например `<имя-проекта>/`, со своими скриптами, README, requirements.txt, примерами конфигурации и локальной .venv. Рабочие отчёты и логи проекта хранятся в его runs/, исключённом из Git.

Все такие подпроекты публикуются в этом репозитории: https://github.com/Star-Vector-MSC/BD-to-Sheets. Вложенные Git-репозитории не создаются. Изменение уже существующей выгрузки выполняется в её текущем проекте, без создания дубля.
